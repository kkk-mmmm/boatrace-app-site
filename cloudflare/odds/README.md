# 5分間隔の3連単オッズ更新

WorkersのCron Triggerを5分間隔で設定し、Durable Objectで取得対象・最新オッズ・取得状態を共有します。閲覧は保存済みの結果を返し、公式の取得を起動しません。KVは使用しません。

## 動作と制限

- Cronは `*/5 * * * *`。処理が遅い場合は重ねず、更新間隔が5分を超える場合があります。全場の同時更新は保証しません。
- Pagesの `data/odds-targets.json` から当日の締切前レース・120通りの予想確率・予想版を取得します。別日、不正な対象、重複、不正な確率は拒否します。
- 各更新で公式のrobots.txtを確認します。取得開始は全体で250ms以上・同じ場で1秒以上空け、同時通信は最大6件です。同じレースへの試行は前回から5分以上空けます。
- 1回のAlarmで最大24レースを処理し、続きは次のAlarmへ引き継ぎます。Freeの外部サブリクエスト上限50件を超えないよう分割します。
- Workers標準のHTMLRewriterで120通り分の表構造を検証します。倍率0・未提供の組番は計算から除外します。公式への接続可否・取得条件・許容頻度は本番でも確認が必要です。
- 失敗時は前回の倍率・取得時刻を保持し、失敗状態を返します。取得時刻を書き換えません。締切後・取得失敗・10分より古い値を期待値やねらい目の対象にしません。
- 全場のねらい目は全120通りを比較します。出走表側の確認が10分より古い場合もねらい目から除外します。
- 当日の最新値を保存し、日替わりで前日の共有状態を削除します。過去オッズの検証用アーカイブは別途必要です。締切前の保存予想は変更しません。

## ローカル確認

Node.js 24で検証。互換性を確認したWrangler 4.100.0／Miniflare 4.20260611.0に固定しています。既存アプリの実行には追加パッケージは不要です。

```bash
cd cloudflare/odds
npm ci --ignore-scripts
npm test
npm run check
```

`check`はデプロイせずバンドルと設定を確認します。開発リポジトリでは桐生・浜名湖の実資料をWorkersのHTMLRewriterでも検証します。公開用の一式には取得原資料を含めず、共通ロジックのテストを収録します。

## 本番接続

接続先は `site/odds-provider.json` の `api_url` で管理します。初期値は `null` です。Actions Variableの `BOATRACE_ODDS_API_URL` が設定されている場合はそちらを優先します。GitHubの変数操作権限がなくても、レビュー対象の設定ファイルで接続・切り戻しを行えます。

1. Cloudflareでプラン・Freeの利用上限を確認します。SQLite型Durable Objectsを使います。有料プランへの変更はコードでは行いません。
2. `kkk-mmmm/boatrace-app-site` のActions Secretsへ `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を登録します。APIトークンは対象アカウントのWorkersを編集する範囲に限定します。認証情報をチャットやコードに貼らないでください。
3. Actionsの **Deploy Cloudflare odds worker** を手動実行します。テスト後にデプロイし、ログへWorkerのURLが表示されます。ローカルなら `npx wrangler login` → `npm run deploy` でも実行できます。
4. 先にPagesの `data/odds-targets.json` が公開されていることを確認します。Workerのログ、Cron実行、`/v1/odds?date=当日の日付` で公式への接続と取得時刻・状態を確認します。テスト資料の成功だけで本番の取得成功とは判断しません。
5. 本番の取得確認後、公開用リポジトリの `site/odds-provider.json` の `api_url` に `https://実際のWorkerホスト/v1/odds` を設定します。このURLは秘密情報ではありません。代わりにActions Variableの `BOATRACE_ODDS_API_URL` も使用できます。
6. **Refresh and publish approved site** を手動実行します。変数の設定時だけActions側のオッズ取得を停止し、画面の接続先とCSPを変更します。出走表・展示・予想保存・日次結果照合は継続します。
7. 公開画面で5分経過後の更新、全120通りからの期待値上位10点、ねらい目、失敗時の参考表示を確認します。無料枠の超過時は停止する可能性があり、利用量を監視します。

ブラウザの確認も5分間隔で、非表示タブでは定期確認を停止します。表示へ戻ったときや場の切り替えでは共有値を利用します。取得と確認のタイミングが合わない場合、表示までさらに最大約5分かかる場合があります。取得時刻と10分の鮮度上限で判定します。

## 切り戻し

`site/odds-provider.json` の `api_url` を `null` に戻し、設定していれば `BOATRACE_ODDS_API_URL` 変数も削除して、承認対象コミットの更新とPages更新を実行するとActions側の取得へ戻ります。WorkerのCronも `wrangler.jsonc` の `crons` を空配列にして再デプロイして停止します。保存予想は変更しません。

## API

```text
GET /v1/odds?date=2026-10-22
GET /v1/odds?date=2026-10-22&venue=06&race=12
```

当日のみ、場01〜24、レース1〜12です。任意URLの取得や公開の更新操作APIはありません。CORSはPagesのオリジンを許可しますが、認証・料金制限ではありません。共有値の読み取り回数と公式取得回数を分けて監視してください。
