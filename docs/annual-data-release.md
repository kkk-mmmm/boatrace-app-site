# 年次選手履歴とCloudflare配信

出走表と展示情報はCloudflareの定期処理だけが公式HTMLを取得し、全閲覧者で共有します。閲覧や更新ボタンは公式への取得を発生させません。時刻は予定締切を基準にします（実際の発走時刻の取得ではありません）。

- 出走表：日本時間7時以降の初回取得、締切30分前の再確認。失敗時は5分以上空けて再試行。
- 展示：締切15分前。未提供なら5分前に再確認。展示が未提供なら欠損と表示。
- オッズ：締切30分以内は1分、それより先は5分間隔。定期処理の遅延・公式の未提供で遅れる場合あり。
- ねらい目：表示更新時点から締切まで1時間以内、新鮮なオッズで推定確率×オッズが1.0超のレースを期待値順に表示。
- 提案：締切3分前以前の最新の有効な予想とオッズを固定。後から取得した値で当時の提案を作りません。当日の締切後も表示できます。

履歴はGitHub Actionsで公式の日別結果アーカイブ（K形式）を1日1ファイル取得します。初回は365ファイル、以後はキャッシュにない日だけ取得し、直近365日を再集計します。アーカイブには全場の結果、登録番号、枠番、実際の進入、着順、ST、展示タイム、決まり手が含まれます。展示STは含まれないため、展示STと本番STの年次乖離を作りません。取得元URL・SHA-256・解析除外をcoverage.jsonへ記録します。6艇の登録番号と枠を確認できないレースは除外し、多数の解析失敗や欠損日があれば更新を停止します。

年次モデルv3は選手・枠別の1着率、着順点、STと安定度、ST順位、展示順位と着順の差、決まり手、開催日次と区分別STを使用します。少数の履歴は母集団へ縮小します。枠番と進入コースは区別します。枠別着順点は1〜6着を10・8・6・4・2・1点、異常着順を0点として計算し、欠場は除外します。公式の級別・グレードを加味した勝率ではありません。ST順位は正常な6艇のSTから算出し、同タイムは平均順位、F/L等のあるレースは未集計です。

履歴は日次更新、係数は固定して日々の少数データへの過適合を避けます。日本時間の暦月ごとに初めて成功した日次実行で学習候補を1回作り、時系列の検証結果を保存します。候補は同じ未使用期間で現行と比較し、件数・確率誤差・的中率・日単位の統計的な改善条件を満たす場合だけ自動採用します。詳細はdata-improvement-verification.mdを参照します。日次のデータ更新でコードや公開承認を変更することはありません。

モデルの検証は古い約305日を学習、その後30日を係数選択、最後30日を未使用の評価に分けます。当日結果を当日の履歴へ混ぜません。正常な6艇の確定着順を確認できるレースが学習・的中率評価の対象です。過去アーカイブによる検証は、実運用の締切前保存や将来の収益性を証明するものではありません。展示のない早い時間の予想やオッズの変動は別途評価が必要です。

GitHub Pagesは共有APIから静的表示データを生成し、ブラウザーも同じAPIを利用します。「配信確認時刻」と公式の「出走表／展示／オッズ取得時刻」は別々に表示します。API障害では古い値を最新と表示せず、保存提案を保持します。年次モデルが3日を超えて古くなると、新しい年次予想への適用を停止します。

場別モデルv3.1は既存14項目に、場・枠別1着率の全国比（対数）、場・枠別着順点の全国差、選手の決まり手傾向と場の決まり手分布の適合を追加します。場・枠ごとの履歴は300走相当の全国事前分布へ縮小し、未知の場の3項目は0とします。枠番と実進入、1枠1着と逃げは区別します。選手能力も同時に学習する観測データのモデルで、場の水面条件だけの因果効果を証明するものではありません。

場別候補の初回構造変更は通常の月次係数候補と別に、完了した1年の古い期間で学習・中間30日で係数選択し、最後30日の同一レースで公開モデルと比較します。採用後は日次で場の集計も更新し、月次候補も17項目で学習します。旧v3.0の14項目と保存済みの提案は引き続き読み込めます。場別履歴は追加の公式ページ取得をせず、既存の結果アーカイブから集計します。

初回の場別項目導入は構造変更のため、2,000レース・20日以上、対数損失の改善と日単位95%区間での改善、上位10点の的中率・Brier誤差の非悪化で判断します。導入後の月次係数のみの自動更新は、従来どおり改善幅0.01以上も要求します。
