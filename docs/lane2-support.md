# 枠番2号艇の逃がし率とv3.3候補

2026-10-31確認時の公開用モデルファイルはv3.1。v3.2の実進入2コース＋決まり手「逃げ」の特徴量は集計・候補機能として存在するが現行モデルでは未適用だった。今回のユーザー定義はこれと別で、枠番2号艇の選手が出走したとき、枠番1号艇が1着になった回数÷対象出走回数。展示進入・実進入が替わっても、決まり手が抜き等でも数える。正常完走の6艇・着順重複なしを対象にする。因果的なアシストを断定する値ではない。

`race_context.lane2_support`に母集団と選手別のn/one_winsを別途保持し、旧course2は変更しない。PythonとJSの集計を突き合わせ、日次の365日ローリング履歴へ追加。元結果・保存予想は書き換えない。

補正率は(racerの勝利数＋20×全体率)/(racerの出走数＋20)。新特徴量は、補正率と全体率のlog-odds差（±2で制限）を1号艇のスコアだけへ渡す。欠場・未集計・不正な件数は0。v3.3はv3.2の23項目＋この1項目で、旧バージョンの意味・係数・特徴量を変えない。新係数は学習ステップごとに非負へ射影し、検証時にも負値を拒否。全6艇のスコアから既存のPlackett–Luceで120通りへ再正規化する。単純な％加算ではない。

## 学習と有効化

データ履歴は日次、係数の再学習は月1回を維持。`monthly_candidate.mjs`の新規候補を`train_annual.mjs --lane2`に変更。既存月の候補・判定は上書きしない。次の新しい月の作成からv3.3を学習する。

既存の前日までの365日収集、過去日だけから特徴量作成、最終60日より前の学習、次30日の係数・温度選択、最後30日の未使用評価、現行モデルとの同期間比較を維持する。2000レース・20日以上、log-loss差-0.01以下、top10非悪化、Brier非悪化、日単位95%区間上限が0未満の場合だけ自動採用。不通過なら現行を保持する。係数0ならこの特徴量は未適用と画面に示す。

本変更の公開だけで本番モデルをv3.3へ切り替えたとは扱わない。マージ後、まずDeploy Cloudflare odds workerをmainで再デプロイしてv3.3の読込みに対応させる。その後Daily rolling-year player profiles and monthly validated coefficient updatesを通常実行し、日次履歴と次の月次判定を確認する。採用後はモデルデータPR・サイト再公開とWorkerの既存のモデル再読込を経て反映する。初期集計完了までは未集計と表示する。

ローカルでは実1年分の完全なraces.jsonを取得できていないため、性能改善は未確認。単体テストは定義の一致・少数例の縮小・欠場時0・高低での確率の単調性・120点合計1・旧版互換を確認する。収益や精度の改善をテスト結果から推定しない。
