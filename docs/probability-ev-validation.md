# 確率・期待値の観測検証 v1

公開場所は `/verification/` の「確率・期待値の検証（直近30完了日）」、配信JSONは `/data/validation.json`。既存の直近7日のレース別記録・31日間の4艇BOX企画とは別集計です。モデルの係数・学習周期・企画条件を変更しません。

## 入力と固定ルール

`site/validation-review.mjs` の VALIDATION_POLICY（probability-ev-v1）を使います。期間は当日を除く直近30完了日。日付はAsia/Tokyo、表示時刻は分まで、判定時刻の精度は維持します。各サイトビルド時にGitHubのverification-dataブランチから読み出した保存記録と結果だけで再計算し、追加の公式取得は行いません。予想・結果の原本は読み取り専用です。

- 保存予想の内容・受信時刻・整合性ハッシュを既存validateRecordで検証。
- 1レースにつき受信区分ごとに保存時刻が最も新しい予想を採用。同時刻なら受信時刻が早いもの、さらに同じなら記録IDの辞書順。結果・払戻を見て選ばない。
- 締切3分前までに受信した記録と、Workerの保存時刻だけに依存する記録を別集計。前者でも独立した第三者の時刻認証ではありません。
- 係数ハッシュで分離。係数不明はモデルIDごとに分ける。初期選択は事前受信・係数確認済み・最新対象日を優先し、同日なら件数順。成績で選ばない。
- 保存結果のSHA整合性と既存の公式資料・Worker結果の検証を使用。取得元間の不一致、6艇・登録番号の重複/選手不一致、F/L・欠場・異常着順・返還・同着、明示された履歴窓の未来混入は除外。
- 未照合は待ち状態。不的中に数えない。正常着順は払戻未取得でも確率検証に使う。オッズ120通りと公式払戻が揃う同じレースだけを金銭比較する。欠損を0円の損失としない。
- 両戦略は全120通りから確率上位10点と期待値上位10点、各点100円（毎レース1,000円）の固定ルール。同値は買い目の辞書順で、画面と共通のpredictionRankingを使う。7日実績の同値処理も同じ関数に統一。開始済みの4艇BOX企画は事前条件を維持し、別の検証として扱う。点数・期待値の閾値を結果から最適化しない。

初回の方式導入日は2026-10-27です。それ以前の記録の集計は観測的な監査であり、未知期間の確認的試験として扱いません。方式を公開後の記録にも固定して蓄積し、将来の改善案は別の未使用期間で確認します。

## 指標

- 対数損失：的中した3連単の `-log(p)` のレース平均。
- Brier：全120クラスの `(p - 正解0/1)^2` の和をレース平均。120で割る二値平均とは尺度が違う。
- 一様確率の参考：対数損失 log(120)、Brier 119/120。最低限の参考であり市場優位性の比較ではない。
- 確率帯：3連単120点、艇ごとの1着確率（1着の20買い目を合算）、確率上位10点の確率合計について、平均推定確率と実際の的中率を比較する。下限以上・上限未満、最終上限は含む。
- 期待値帯：固定した帯に入る全買い目を各100円買った仮想回収率。推定回収率は `100 × 平均(p×保存オッズ)`、実回収率は `100 × 公式払戻合計 / 仮想購入合計`。上位10点戦略とは別の集計。
- 上位10点戦略：推定的中率と実的中率、推定回収率と実回収率、その差。確定払戻を保存オッズで代用しない。
- 場・グレード別：探索的な内訳のみ。有意差・最良条件の断定をしない。

## 不確実性

同日のレースをひとまとまりとして日を復元抽出し、同じ抽出で指標と戦略差を計算するpaired day-block bootstrapです。乱数種20261027、1,000回、両側パーセンタイル2.5%/97.5%（保守的な下側floor/上側ceil）。対数損失、Brier、上位10点の的中率校正差、期待値上位回収率、確率上位との差、推定回収率との差を出します。

レースを等重み、金銭は購入額を分母に集計します。各日のレース数が違っても日平均の単純平均に置き換えません。同じレースの120買い目を独立120標本とみなしません。区間は2,000レースかつ20完了日から表示、金銭区間は完全オッズ・払戻を持つレースについて独立に同条件を要求します。

この下限は少数標本の過大評価を避ける運用基準で、統計的十分性や利益を保証する基準ではありません。日をまたぐ依存、非定常な市場・出走構成、厚い裾の払戻分布、選択バイアスは残ります。95%区間は将来の値の95%保証ではなく、観測標本に対する仮定付きの参考です。日付・受信区分・係数版・固定帯・入力ダイジェストを残し、都合の良い期間や条件を事後に選ばない運用が必要です。

## 更新・運用

既存の結果照合とサイト公開で自動更新されます。当日は7日の日別記録で確認し、翌日以降に30完了日集計へ入ります。更新失敗時は直前の表示を残し、別ステータスで失敗を知らせます。件数は受信区分別のため同一レースが区分間で重なり、合算しません。未保存の全開催レースまでは網羅を保証しません。

入力ダイジェストはポリシー・選択した保存記録ID/整合性ハッシュ・照合結果からSHA-256を計算します。改変検出は完全な第三者監査・署名による真正性証明とは異なります。

月次の係数採用は既存の時系列ホールドアウト・対比較・主評価指標の条件を維持します。この画面の回収率を見て係数を調整したり、成績のよい候補を同じ期間で再選択したりしません。次の改善案は仕様を事前固定し、以後の未使用期間で検証してください。
