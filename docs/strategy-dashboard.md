# 条件別成績・充足率と確率補正候補

v1.36.0は `/strategies/` を追加し、予想実績ページからリンクします。`data/strategies.json` の保存済み条件別記録を日付・場コード・グレード・係数版・イン/それ以外・10/20点で比較します。係数・受信区分・条件は分離し、回収率は購入額で加重。見送り・結果待ち・欠損・異常を購入損失に入れません。日別の推移は折りたたみで確認できます。記録がない場合は未集計と表示します。

充足率は有効化後、締切3分前基準までに取得できた開催予定をinventoryへ追記し、その基準時刻を過ぎた既知のレースだけを分母とします。予定取得前に固定された記録は分母へ後付けしません。既知の欠場予定は分母から除外。予想保存、全120オッズ、6艇の展示タイム/ST/進入、正常な公式払戻までの照合を別に集計します。予定自体の欠落は検出できず、全開催レースの網羅率とは異なります。取得充足率はページの成績フィルターと独立した全記録です。

固定予想が基準から15分以上経っても保存されない場合、または結果/払戻が締切から1時間以上待ちの場合は監視対象として表示し、既存の保存ジョブで `Data coverage gaps` のwarningを出します。`verification-data` の `reports/coverage.json` に機械可読の件数を残します。これは新規の公式リクエストを発生させません。展示の未提供と通信失敗は現状の集計だけでは区別できず、未充足として表示します。

確率補正は `calibration_review.mjs` に温度補正候補0.7/1/1.3/1.7/2を用意しました。90完了日の保存記録を読み、係数版・受信区分別の日付前半だけで対数損失が最小の候補を選び、後半では候補を変更せず未補正と対数損失・Brier・期待値上位10点の実払戻を比較します。元の確率・係数・予想記録は変更しません。

前半・後半それぞれ20日/2,000件がなければINSUFFICIENT_DATA。揃ってもREADY_FOR_FURTHER_REVIEWであり、自動採用しません。過去データを見た後の探索を真の将来期間の検証とみなさず、月次の採用判断には未使用の将来データや不確実性評価を別途確認してください。毎回の公開ビルドで `data/calibration.json` を更新し、記録が増えるたびに候補比較を継続できます。本番係数の再学習・採用周期は変更しません。

本番の既存記録が接続できないローカル環境では空集計となり、新しい実績数や補正効果を捏造しません。ページ・保存・候補選択のテストは合成データで検証し、最新本番データの確認とは分けます。
