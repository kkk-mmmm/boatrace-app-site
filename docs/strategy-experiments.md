# 条件を固定する検証企画

第1弾は2026年10月27日〜11月26日（日本時間）、全24場を対象とする。実際の購入・自動投票はしない。

## 固定した選定ルール V1

- 公開後に保存処理が最初に実行された時刻を activation.json に一度だけ記録する。開始前の予想・レースを事後補完しない。
- Workerが締切3分前に固定した予想のみ使用する。予想保存が activation より前の場合は使わない。実オッズの取得は3分前ちょうどとは限らず、既存の有効期限10分以内の保存値を使用する。
- 通常の6艇、全120通りの予想とオッズを確認できた場合のみ、期待値（確率×オッズ）上位10点を選ぶ。
- 10点の1〜3着の全位置における艇の登場回数を数える。同数は、その艇が含まれる上位10点の期待値合計が高い順、さらに同点なら艇番の昇順で決定する。
- 選んだ4艇の3連単24通りを各100円、計2,400円購入したと仮定する。上位10点にないBOX買い目も含む。
- 事前の全艇1着確率、1号艇1着（イン逃げ想定）とそれ以外、BOXの的中確率、期待回収率、上位10点・頻度・全24点・保存時刻・モデル係数・グレード・原本IDを記録する。1号艇1着は実際の決まり手「逃げ」の確率とは区別する。

## 保管と照合

`verification-data` ブランチの `experiments/<id>/` に定義、activation、予定、選定予想を追記専用で保存する。同じIDの定義変更と選定の上書きを拒否する。選定は元の snapshots レコードとハッシュ・決定計算を再照合する。Worker記録時刻を使うもので第三者時刻証明ではない。

サイト取得と連動するおおむね5分間隔の capture で固定予想を拾い、毎時15分を目安にCloudflareで取得済みの当日確定結果と照合する。未照合の締切5分後以降の予想だけを対象に共有APIを1回読み、確定結果を `live-results/<date>/<venue>/R<n>.json` へ追記専用で保存する。対象がなければAPI取得を行わず、新しい記録がなければ再公開しない。履歴の再取得や係数の再学習は行わない。翌日02:10開始の日次処理による公式結果アーカイブの照合も残す。GitHub Actionsの実行と公開は遅延し得る。照合のための公式サイトへの追加取得は行わず、確定結果を保存した後にサイトの再公開を開始する。

公開APIの7日・SQLite内部30日とは別に、選定・原本・公式結果はGitの専用ブランチへ保持する。31日分が7日・30日で消える設計にはしない。公開ビルドは `VERIFICATION_DIRECTORY` の記録を読み、`data/experiments.json` へ目次・集計を、日付単位のJSONへ詳細を書き出す。ホームでは検証データを取得せず、検証記録を開いた時だけ目次を読み、最新の日付から詳細を読む。全期間を選ぶ操作で全日を読み込める。

結果のファイルハッシュ・選手・レース・公式3連単払戻を確認する。当日分はWorkerの公式結果URL・取得時刻・レース・選手を検証し、取得済みの結果だけを保存する。WorkerのHTML原本ハッシュや第三者時刻証明とはみなさない。後日アーカイブと結果・払戻が食い違う場合は確認待ちの集計対象外とし、勝手に上書きしない。F/L・欠場・同着・返還等は通常評価から除外する。未照合や予想欠損を不的中にしない。既知の予定と24場の開催状況確認を記録し、未取得レースが存在し得ること・欠損件数を明示する。開催状況自体が未取得のレースは全数を保証できない。

## 指標・記事

回収率は照合済みレースの仮想払戻合計÷仮想購入合計。事前期待回収率も同じ照合済み標本で集計し、その差をパーセントポイントで示す。元の期待値上位10点を各100円購入する基準戦略との回収率差も併記する。日付・場・グレード・1号艇1着確率帯・最有力艇1着確率帯・モデル係数別の件数と回収率を表示する。確率帯は30%未満、30〜50%未満、50〜70%未満、70%以上で事前固定する。少数標本・条件構成の差に留意し、因果や収益改善を断定しない。

期間終了後も未照合があれば「結果照合中」とし、公式の日次アーカイブと照合が揃った処理で `article.json` を一度だけ確定する。記事には条件、本文、集計、全レース詳細を保持し、以後の自動処理では書き換えない。終了記事は #archive の検証企画カードから展開できる。追加の検証は既存定義を変更せず新しいIDで追加する。過去の桐生15件は別の折りたたみ欄へ保管する。
